PROJECT 2 DESIGN - MILESTONE 1 INTEGRATION

MODULES AND LOADING
main.cpp constructs CampusGraph, FacilityDatabase, and DepartmentTree, loads
buildings, connections, facilities, then departments, and runs the menu.
The optional data-directory argument defaults to data/ relative to the current
directory. Files are never rewritten. Missing files report errors and zero
summaries; later files and the menu still run. TextUtils trims outer whitespace
including CRLF, preserves internal spaces, splits complete pipe records while
retaining empty fields, and normalizes ASCII comparison keys.

FACILITIES AND CUSTOM HASHING
Facility retains uppercase ID, name, canonical building, and category.
HashTable owns accepted records in file order and growing bucket chains of
record indices. ID insertion, duplicate detection, and lookup use only the
selected bucket, never a library hash container or a full-record ID scan.
Each ID is trimmed, uppercased, and validated as F plus exactly three digits.
The custom formula processes the normalized characters in order:
  h0 = 0
  h(i+1) = (31 * h(i) + unsigned ASCII value of key[i]) modulo capacity
DEFAULT_CAPACITY is 17; a positive constructor parameter can override it.
Separate chaining was chosen because chains grow beyond the bucket count,
avoiding full-table rejection without resizing or an arbitrary record limit.
One collision is counted per accepted insertion into a previously nonempty
bucket, not per comparison. Invalid/duplicate IDs change no records or counts.
Lookup is expected O(1 + n/b), worst O(n), for n records and b buckets;
storage is O(b + n), plus record text. Vector ownership releases all storage.

FacilityDatabase validates field counts, nonempty fields, IDs, and references
against the graph's accepted building names, retaining their first spelling.
Category matching scans only accepted records to preserve the first accepted
category spelling; rejected records cannot register an ID or category.
Warnings include filename, physical line, and reason. Summaries include both
load counts and hash capacity/entries/collisions. Display preserves file order.
ID search distinguishes invalid, normalized not found, and complete found.
Record pointers expire on the next load. Categories are not another hash table.

CAMPUS GRAPH
Sulav's CampusGraph uses a vector of building names and an adjacency list of
neighbor-index vectors. This fits sparse campus connections in O(V + E)
storage and naturally preserves building and neighbor insertion order.
An accepted undirected edge updates both endpoints and increments the total
once. Duplicate/reversed edges, self-connections, and unknown references are
rejected. Building matching ignores case and outer whitespace.
BFS uses std::queue, a visited vector marked at enqueue, and edge distances.
It visits neighbors in insertion order, includes the start at distance zero,
and handles isolated and unknown starts. BFS runs in O(V + E).
The same representation also supports the supplied Final graph methods;
the Milestone 1 menu exposes only the required Milestone 1 operations.

DEPARTMENT TREE
Aqani's general tree owns children with unique_ptr in insertion-ordered vectors;
a non-owning parent pointer supports search details and depth calculation.
It is not binary. File parents must already exist; the first root uses NONE.
If an accepted department is actually named NONE, later references to it are
ordinary parent references. Duplicate names are rejected ignoring case.
The first menu addition creates a root without asking for a parent; later
additions require an existing parent and affect memory only. Search reports
name, parent (None for root), direct children, and edge depth. Recursive
preorder powers both four-space-indented hierarchy and separate unindented
traversal. Search/traversals are O(D) for D departments. Owned nodes are freed
when the tree is destroyed; copying the tree is disabled.

MENU AND VERIFICATION
Choices 1-9 and 0 follow the required Milestone 1 numbering. getline accepts
names with spaces; isolated integer parsing rejects blanks, text, decimals,
suffixes, overflow, and out-of-range choices without damaging the input stream.
End of input exits cleanly. Component and scripted application tests cover
validation, ordering, collisions, BFS, tree operations, and recovery.
